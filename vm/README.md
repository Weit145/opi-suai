# Виртуальная машина для ЛР №2

## Что развёртывается

Полноценная ВМ QEMU/KVM: Ubuntu Server 24.04 LTS Minimal, 2 виртуальных
процессора, 1536 МБ RAM, динамический диск QCOW2 ёмкостью 16 ГБ.
Диск занимает место по мере записи данных; гостевая ОС содержит swap 1 ГБ.
Графического рабочего стола внутри нет: управление через SSH, Redmine — через
браузер ноутбука. Виртуализация использует аппаратное ускорение KVM.

Внутри гостевой ОС установлены Ruby 3.2, Redmine 6.1.5 из исходников,
PostgreSQL 16, nginx, сервер Puma и Git. Сервисы запускаются автоматически
при загрузке гостевой ОС. Тема Bleuclair включена, язык интерфейса — русский.

Схема подключения: браузер ноутбука → `127.0.0.1:8082` → порт 80 ВМ
→ nginx → Puma (`127.0.0.1:3000` внутри ВМ) → PostgreSQL.
База данных и пользовательские файлы этой ВМ независимы от экземпляров Docker
на портах 8080/8081. Они не переносятся с хоста при первоначальной установке.

## Управление

Команды выполняются в корне проекта на ноутбуке:

```sh
make vm-up
make vm-status
make vm-check
make vm-ssh
make vm-logs
make vm-down
```

`vm-up` при первом вызове скачивает официальный образ Ubuntu, проверяет
SHA-256, создаёт SSH-ключ и конфигурационный диск cloud-init. Установка Redmine
выполняется внутри ВМ при первой загрузке; для неё нужен интернет.
Прогресс доступен через `make vm-logs`, итог — строка `READY`.
До запуска SSH журнал загрузки можно прочитать на хосте:

```sh
tail -n 50 .vm/serial.log
```

После установки откройте http://localhost:8082. Логин администратора — `admin`,
пароль находится в `.vm/credentials.txt` на ноутбуке. Это отдельный пароль,
а не стандартный `admin`. Пользователь гостевой Ubuntu — `student`; вход
через `make vm-ssh` по отдельному SSH-ключу, `sudo` доступен без пароля.
HTTP и SSH проброшены только на loopback ноутбука (порты 8082 и 2222).

`vm-check` проверяет HTTP, ресурсы темы, вход администратора и сохранённую
настройку Bleuclair. Использует пароль из `.vm/credentials.json`; если вы
смените пароль в интерфейсе Redmine, обновите его там перед этой проверкой.

`vm-down` отправляет штатный сигнал выключения ACPI и сохраняет диск.
Следующий `vm-up` запускает ту же ВМ с существующими настройками и данными.
После обычного запуска дождитесь загрузки ОС и приложения (на этом ноутбуке
около минуты); готовность показывает `make vm-status`.
Автоматический запуск ВМ при включении ноутбука не настроен.
После перезагрузки ноутбука выполните `make vm-up`.

## Файлы и резервное копирование

- `vm/manage.py` — создание, запуск, состояние, SSH и выключение ВМ.
- `vm/provision.sh` — последовательность установки внутри гостевой ОС.
- `.vm/disk.qcow2` — записываемый диск гостевой ОС.
- `.vm/ubuntu-24.04-minimal-cloudimg-amd64.img` — исходный диск, нужен для запуска.
- `.vm/seed.img` — первоначальные настройки cloud-init.
- `.vm/credentials.txt`, `.vm/credentials.json`, `.vm/id_ed25519` — локальные секреты.

Каталог `.vm/` исключён из Git и доступен только владельцу. Не добавляйте его
в репозиторий. Для резервной копии выключите ВМ через `make vm-down` и
скопируйте весь каталог `.vm/` на другой носитель. Сохраните оба диска:
записываемый QCOW2 использует исходный образ как backing file.
После переноса на другой путь требуется исправить ссылку на исходный образ
командой `qemu-img rebase -u -b /новый/путь/к/исходному.img .vm/disk.qcow2`
при выключенной ВМ. Применять её следует только к копии с тем же исходным образом.

Внутри ВМ Redmine находится в `/opt/redmine`; база — `redmine`, её владелец —
отдельная роль PostgreSQL `redmine`. Исходный скрипт первичной установки:
`/root/provision-redmine.sh`, журнал — `/var/log/opi-provision.log`.

## Проверки для демонстрации и отчёта

Войдите через `make vm-ssh` и выполните:

```sh
hostnamectl
systemd-detect-virt
ruby --version
git --version
sudo -u postgres psql -c '\l'
systemctl status redmine nginx postgresql --no-pager
sudo journalctl -u redmine -n 30 --no-pager
```

Для просмотра исходников и настроек:

```sh
cd /opt/redmine
ls
sudo -u redmine bash -c 'cd /opt/redmine; set -a; source .env.production; set +a; bundle _2.5.23_ exec rails runner -e production "puts Setting.ui_theme"'
```

Не включайте в отчёт содержимое файлов с паролями и SSH-ключами.
Для Git задано учебное имя `weit`, email `weit@opi-vm.local`. Перед работой
с собственным GitHub укажите свою фактическую почту через `git config --global user.email`.
Существующие ключи и GitHub-доступы хоста внутрь ВМ не копируются.

## Соответствие методичке

В методичке 2021 года приведены VirtualBox, AstraLinux, Redmine 4.0.5,
PostgreSQL 9.6 и Apache/Passenger. Здесь использованы QEMU/KVM, Ubuntu 24.04,
Redmine 6.1.5, PostgreSQL 16 и nginx/Puma. Сохранены отдельная гостевая ОС,
установка Ruby-зависимостей, создание БД, конфигурация подключения,
миграции, загрузка начальных данных и установка темы. Тема Bleuclair взята
из публичного репозитория, а не из комплекта преподавателя. Если преподаватель
требует именно выданные файлы или конкретный гипервизор, эти отличия нужно согласовать.

Роль «Специалист по информационным системам» на стр. 78 также предполагает
получение репозитория с GitHub, добавление условных исходников и README,
отправку изменений и подготовку отчёта. Установка ВМ и Git не заменяет эти
действия. Отправка в GitHub автоматически не выполняется.

Документация: [установка Redmine](https://www.redmine.org/projects/redmine/wiki/RedmineInstall),
[официальные выпуски](https://www.redmine.org/projects/redmine/wiki/Download),
[образ Ubuntu](https://cloud-images.ubuntu.com/minimal/releases/noble/release-20261017/),
[cloud-init NoCloud](https://docs.cloud-init.io/en/latest/reference/datasources/nocloud.html).

## Зависимости хоста Ubuntu

Установлены пакеты `qemu-system-x86`, `qemu-utils`, `cloud-image-utils`,
`openssh-client`. Для повторения на другом Ubuntu-хосте:

```sh
sudo apt-get update
sudo apt-get install --no-install-recommends qemu-system-x86 qemu-utils cloud-image-utils openssh-client
```

Пользователь должен иметь доступ на чтение/запись к `/dev/kvm`. Если его нет,
администратор может добавить пользователя в группу `kvm`; затем нужно
заново войти в сеанс. Для первоначального развёртывания скрипт требует
не менее 5 ГБ свободного места на хосте. Для дальнейшей работы нужен запас
под рост диска. Объём RAM можно изменить перед запуском:
`VM_MEMORY_MB=2048 make vm-up`.
